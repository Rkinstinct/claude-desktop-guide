01

מה יש לכם ואיך המדריך עובד

המדריך הזה כתוב בשבילכם: עובדים עם רישיון ארגוני (Team/Enterprise) בסביבה נעולה. כל מה שתקראו כאן עובד בסביבה כזאת - בלי יוצא מן הכלל, בלי פיצ'רים שהאדמין חסם.

מה יש לכם

  • Claude Chat - השיחה הרגילה: שאלות, כתיבה, ניתוח מסמכים, פרויקטים וארטיפקטים. באפליקציית דסקטופ, בדפדפן ובמובייל.
  • Claude Code - סוכן הפיתוח: כותב, מריץ ובודק קוד על המחשב שלכם. עובד בטרמינל, בתוך אפליקציית הדסקטופ, וב-VS Code.
  • שרתי MCP שטוענים בעצמכם - חיבור של קלוד למערכות שלכם (קבצים, בסיסי נתונים, Fabric) דרך קובץ הגדרות פשוט. פרק 18 מדריך צעד-צעד.
  • סקילים מקבצים - חבילות הוראות שאתם יוצרים או מקבלים, ומעלים בעצמכם. פרק 13.
מה שלא תראו ברישיון נעול - וזה תקין: Cowork (סוכן הענן), סשני ענן של Code, ספריית הקונקטורים וחנות הפלאגינים מושבתים אצל ארגונים רבים על ידי האדמין (באמצעות מדיניות כמו secureVmFeaturesEnabled ו-isDesktopExtensionDirectoryEnabled). אם נתקלתם במדריך אחר שמדבר עליהם - תדעו שהם קיימים, פשוט לא אצלכם. כל שאר המדריך לא תלוי בהם.

איך ללמוד עם המדריך

  1. חלק א׳ (פרקים 1-6): Claude Chat מההתחלה - שיחה ראשונה, פרויקטים, ארטיפקטים, זיכרון וקונטקסט.
  2. חלק ב׳ (פרקים 7-12): Claude Code - התקנה, סשן ראשון, הרשאות, חשיבה מורחבת וסקירת קוד.
  3. חלק ג׳ (פרקים 13-18): הולכים לעומק - סקילים, פקודות, סאב-אייג'נטים, הוקס, CLAUDE.md ו-MCP.
  4. חלק ד׳ (פרקים 19-21): היישום הארגוני שלכם - Skills for Fabric ועבודה עם Power BI.

כל פרק עונה על שלוש שאלות: מה זה, מתי משתמשים, ואיך עובדים - ומלווה בסרטון דמו עברי קצר על הממשק האמיתי.

02

Chat: השיחה הראשונה

Chat הוא המקום שבו מתחילים: שיחה עם קלוד על כל דבר - שאלה, טיוטה, ניתוח קובץ, סיעור מוחות. כמה דקות של היכרות עם המסך חוסכות שעות בהמשך.

מה יש על המסך

  • סרגל צד: צ'אטים אחרונים, פרויקטים והגדרות. צ'אט חדש מתחיל בלחיצה על New chat.
  • תיבת ההודעה (הקומפוזר): כאן כותבים. ה-+ מצרף קבצים ותמונות, והכפתור הימני שולח.
  • תפריט המודל ליד כפתור השליחה: בחירת מודל, רמת מאמץ (Effort) והדלקת חשיבה מורחבת - פרק 10 מתעמק.

השיחה הראשונה - איך עובדים נכון

  1. פתחו צ'אט חדש וכתבו בקשה אחת ברורה: מה רוצים, באיזה פורמט, ובשביל מי.
  2. צרפו חומר אמיתי עם ה-+ במקום לתאר אותו - מסמך, טבלה, צילום מסך.
  3. קיבלתם תשובה קרובה? הגיבו בתוך אותה שיחה מה לתקן. קלוד זוכר את ההקשר לאורך השיחה.
  4. נושא חדש? פתחו צ'אט חדש. שיחות ארוכות ומעורבבות פוגעות בדיוק (פרק 6).

מתי Chat ומתי Claude Code

כלל אצבע פשוט: אם התוצר הוא תשובה, מסמך או ניתוח - Chat. אם צריך לגעת בקבצים, להריץ פקודות או לבנות תוכנה - Claude Code (חלק ב׳). שניהם חלק מאותו מנוי ארגוני.

03

פרויקטים: בית קבוע לנושא חוזר

פרויקט ב-Chat הוא מרחב עבודה לנושא אחד שחוזר על עצמו: הוראות קבועות, קבצי רקע, וכל השיחות בנושא - במקום אחד. אם אתם חוזרים לאותו תחום שוב ושוב, פרויקט חוסך את ההקשר מחדש בכל פעם.

מתי פותחים פרויקט

  • דוח שבועי חוזר, לקוח קבוע, מסמך שמתעדכן - כל נושא עם הוראות וחומרים קבועים.
  • לא מתאים ל: שאלה חד-פעמית או נושא שמשתנה בכל שיחה.

איך בונים פרויקט שעובד

  1. יוצרים פרויקט חדש ונותנים שם ברור.
  2. כותבים הוראות (Instructions) קצרות וקונקרטיות: מי הקהל, איזה טון, איזה פורמט פלט, מה אסור.
  3. מעלים קבצי רקע שההוראות מפנות אליהם: דוגמאות, תבניות, מונחון.
  4. עובדים בתוך הפרויקט - כל שיחה חדשה בו כבר יודעת את ההקשר.

מלכודות נפוצות

  • הוראות ארוכות ומעורפלות עובדות פחות טוב מהוראות קצרות ומדויקות.
  • שיתוף פרויקט ("Can view" / "Can edit") זמין ברישיונות Team ו-Enterprise.
  • גם ב-Claude Code עובדים "לפי פרויקט", אבל שם הפרויקט הוא תיקיית העבודה על המחשב (עם קובץ CLAUDE.md משלה, פרק 17) - לא אותו פרויקט של Chat.

04

ארטיפקטים: תוצרים חיים, לא עוד תשובה בצ'אט

ארטיפקט הוא תוצר שנפתח לצד השיחה וחי חיים משלו: מסמך, טבלת קוד, ממשק קטן או דשבורד אינטראקטיבי. במקום לקבל את התשובה כטקסט בזרם הצ'אט - מקבלים דבר שאפשר לערוך, לשכלל ולשתף.

מתי קלוד יוצר ארטיפקט

  • תוכן שעומד בפני עצמו: מסמך, דוח, מצגת, רכיב קוד, טבלה גדולה.
  • דבר שתרצו לערוך שוב ושוב - כל בקשת תיקון מעדכנת את אותו ארטיפקט.

איך עובדים איתו

  1. מבקשים תוצר ("תכין דוח מסכם", "תבנה דשבורד קטן מהקובץ") - הארטיפקט נפתח בצד.
  2. משכללים בשיחה: "תוסיף עמודת סה״כ", "תשנה את הכותרת" - הגרסה מתעדכנת.
  3. משתפים או מורידים את התוצר כשהוא מוכן.

טיפ שחוסך זמן

אם קיבלתם טקסט ארוך בתוך הצ'אט במקום ארטיפקט - פשוט בקשו: "תהפוך את זה לארטיפקט". זו הדרך המהירה להעביר תוצר למסלול עריכה נכון.

05

זיכרון, חיפוש ואינקוגניטו

שלושה מנגנונים שולטים במה שקלוד זוכר עליכם - ומתי הוא דווקא לא זוכר כלום. בשליטה שלכם, ובשלוש דקות מבינים את כל התמונה.

זיכרון: מה קלוד יודע עליכם

  1. קלוד מזהה נושאים חוזרים בשיחות שלכם (תפקיד, העדפות, פרויקטים) ושומר אותם כרשימת נושאים.
  2. פתחו Settings ותראו את הרשימה בעצמכם: כל נושא ניתן לעריכה או מחיקה מלאה.
  3. כלל אצבע ארגוני: מידע רגיש שלא הייתם רושמים לעצמכם בפתק - אל תכניסו לזיכרון.

חיפוש בשיחות עבר

מחפשים משהו שנאמר לפני שבועיים? שואלים בשפה טבעית ("מה החלטנו על המחירון של רבע 4?") וקלוד שולף את ההקשר מהשיחה הרלוונטית. אין צורך לזכור איפה זה נכתב.

אינקוגניטו: שיחה שלא נשמרת

צ'אט אינקוגניטו (אייקון הרפאים) לא נשמר בהיסטוריה ולא משפיע על הזיכרון. מתאים לניסוי חד-פעמי, שאלה אישית, או טיוטה שלא צריכה להשאיר עקבות. שימו לב: ברישיון ארגוני המדיניות של הארגון חלה גם כאן.

06

קונטקסט וטוקנים: זיכרון העבודה של קלוד

לכל שיחה יש "חלון הקשר" - כמות המידע המקסימלית שקלוד מחזיק בראש ברגע נתון: ההוראות, הכלים, ההודעות ותוצאות הכלים. כשהחלון מתמלא, הביצועים יורדים. מי שמנהל את החלון נכון - מקבל תשובות טובות יותר.

ב-Chat: לראות ולדחוס

  • טבעת השימוש ליד תפריט המודל מראה כמה מהחלון נוצל בשיחה הנוכחית.
  • כשהחלון מתמלא מתבצעת דחיסה אוטומטית: קלוד מסכם את השיחה ומשאיר את העיקר.
  • /compact דוחס ידנית - כדאי אחרי שלב שהסתיים ולפני נושא חדש באותה שיחה.

ב-Claude Code: שלוש פקודות ששוות זהב

  • /context - מציג מה טוען את חלון ההקשר כרגע ואיפה התקציב הולך.
  • /compact - סיכום השיחה לשחרור מקום, אפשר עם הוראות מיקוד.
  • /clear - מנקה את היסטוריית השיחה לגמרי (זיכרון הפרויקט נשמר). לפתיחת נושא חדש.

חמישה כללי עבודה

  1. שיחה חדשה לנושא חדש - הכלל החשוב מכולם.
  2. תנו לקלוד למשוך קבצים בעצמו במקום להדביק תוכן ענק לתוך הצ'אט.
  3. משימה ענקית? חלקו לשלבים, דחסו ביניהם.
  4. מסמך שחוזרים אליו הרבה? שימו אותו בפרויקט במקום בכל שיחה מחדש.
  5. מעל ~70% בטבעת? זמן לדחוס או לפצל.

07

Claude Code: מה זה, התקנה והגדרה

Claude Code הוא סוכן הפיתוח של קלוד: הוא קורא וכותב קבצים על המחשב שלכם, מריץ פקודות, בודק תוצאות ומתקן את עצמו. בניגוד ל-Chat שמחזיר תשובה - Code מבצע עבודה מקצה לקצה בתוך הפרויקט שלכם.

איפה הוא רץ

  • אפליקציית הדסקטופ: לשונית Code - הדרך הכי נוחה להתחיל, הכל בתוך האפליקציה שכבר יש לכם.
  • טרמינל: מריצים claude בתיקיית הפרויקט. הדרך הקלאסית של מפתחים.
  • VS Code: הרחבה רשמית שמחברת את הסשן לעורך - רואים דיפים ועריכות בתוך ה-IDE.

התקנה ברישיון ארגוני

  1. ודאו שיש לכם גישה: ברוב ארגוני ה-Team/Enterprise הזיכיון כולל Claude Code (בארגונים ישנים - תלוי בסוג המושב).
  2. דרך אפליקציית הדסקטופ: התקינו את האפליקציה והתחברו עם חשבון הארגון - לשונית Code מחכה בפנים.
  3. דרך הטרמינל: עקבו אחר הוראות ההתקנה הרשמיות לסביבה שלכם, והתחברו עם חשבון הארגון בהפעלה הראשונה. אל תריצו התקנה עם sudo - זה שובר הרשאות קבצים בהמשך.
בסביבה נעולה: אם ההתקנה נחסמת (אין הרשאות אדמין, רשת חוסמת, מדיניות MDM) - זה לא כשל שלכם. פנו ל-IT ובקשו התקנה מאושרת של Claude Desktop ו-Claude Code; האדמין שולט בזמינות דרך מדיניות (isClaudeCodeForDesktopEnabled). גם התקנת VS Code עצמו דורשת אישור IT ברוב הארגונים.

VS Code כסביבת העבודה

מומלץ לעבוד עם עורך קוד לצד הסוכן: VS Code הוא הבחירה הנפוצה, וההרחבה של Claude Code מציגה את הדיפים והעריכות ישירות בעורך. לא חובה - אפשר לעבוד גם מהדסקטופ או הטרמינל בלבד - אבל עם עורך הסקירה נוחה יותר.

08

סשנים, סביבות והפרויקט הראשון

כל שיחה ב-Claude Code היא סשן: היסטוריה משלה, תיקיית פרויקט משלה, שינויי קוד משלם. אפשר להחזיק כמה סשנים במקביל מהסרגל, ו-Cmd+N פותח סשן חדש.

הפרויקט הראשון שלכם - צעד אחר צעד

  1. צרו תיקייה חדשה למשימה (למשל expenses-board) ושימו בתוכה את קובץ הנתונים - נגיד קובץ אקסל של הוצאות.
  2. פתחו סשן בתיקייה הזו (מלשונית Code בדסקטופ, או claude מהטרמינל בתוך התיקייה).
  3. תנו הנחיה מדויקת: מה לבנות, מאיזה קובץ לקחת את הנתונים, ואיך התוצאה צריכה להיראות. "בנה דשבורד HTML שמסכם את ההוצאות מהקובץ, מחולק לקטגוריות, עם גרף חודשי" עובד הרבה יותר טוב מ"תעשה משהו עם האקסל".
  4. עקבו אחרי הפעולות שהוא מבצע, אשרו את מה שדורש אישור, ובקשו תיקונים בשיחה - "תוסיף סינון לפי חודש", "תשנה צבעים". ככה נראית עבודה נכונה: איטרציות קטנות, לא ניסיון אחד ענק.

עבודה מקבילה נכונה

  • כל סשן עובד על עותק מבודד של הריפו (worktree) - שני סשנים לא דורסים אחד את השני.
  • Cmd+; פותח שאלת צד: רואה את ההקשר בלי לגעת בשיחה הראשית (שקול ל-/btw בטרמינל).
  • ארכיון סשן תמיד מבקש אישור, ומתקבלת התראה כשסשן מסיים.
  • /resume (או /continue) פותח סשן קודם וממשיך מאותה נקודה.
שורת יושרה לסביבה נעולה: ישנם גם סשני ענן שממשיכים לרוץ אחרי שהמחשב נסגר - הם חלק מ-Cowork ולא זמינים ברישיון נעול. כל מה שבפרק הזה עובד מקומית, בלי ענן.

09

מצבי הרשאות: כמה עצמאות לתת לקלוד

מצב ההרשאות קובע מתי קלוד שואל רשות לפני שהוא נוגע בקבצים או מריץ פקודות. זה אחד ההחלטות החשובות בעבודה עם Claude Code - והיא משתנה ממשימה למשימה.

מצבמה קורה בפועלמתי
Manualשואל לפני כל עריכת קובץ וכל פקודה; רואים דיף ומאשרים או דוחיםקוד רגיש, לימוד הכלי, כשעוד לא סומכים
Accept editsעריכות קבצים מתאשרות אוטומטית; פקודות טרמינל עדיין שואלותכשסומכים על הכיוון ולא רוצים לאשר כל דיף
Planחוקר וקורא בלי לגעת בכלום, ומציג תוכנית מלאה לאישורמשימה מורכבת - קודם מסכימים על הגישה
Autoמבצע לבד עם בדיקות בטיחות ברקעמשימות שגרתיות ומוגדרות היטב
Bypass permissionsבלי אישורים בכללרק בסביבה מבודדת (קונטיינר) - לא על קוד אמיתי

אם הגעתם מחומר ישן - מיפוי השמות

בקורסים ותיעוד מהתקופה של הטרמינל המצבים נקראו אחרת: ask before edits הוא המצב הרגיל (Manual), auto-accept edits הוא Accept edits, plan mode נשאר Plan, ו-bypass permissions נשאר Bypass. מצב Auto הוא תוספת חדשה. בטרמינל, Shift+Tab מחליף מצב בלחיצה.

הזרימה המומלצת למשימה מורכבת

  1. פותחים ב-Plan: קלוד חוקר את הקוד ומציג תוכנית עם צ'ויור - בלי לגעת בקובץ אחד.
  2. סוקרים, מתקנים את התוכנית, מאשרים.
  3. עוברים ל-Accept edits לביצוע, ועוקבים.
  4. משהו השתבש? Esc עוצר מיד, ו-Esc Esc (או /rewind) מחזיר לצ'קפוינט קודם.

הרשאות מתקדמות: חריגים קבועים

מעבר למצב הרגעי, אפשר להגדיר כללי allow/deny קבועים לכלי או פקודה ספציפיים (למשל: תמיד לאשר git status, לעולם לא לאשר rm -rf) דרך /permissions או קובץ ההגדרות. ככה המצב נשאר שמרני, והחיכוך היומיומי נעלם.

10

חשיבה מורחבת ורמת מאמץ

לפני שקלוד עונה, אפשר לשלוט בשני בוררים: כמה מאמץ (Effort) הוא משקיע בתשובה, והאם הוא עובר חשיבה מורחבת (Extended Thinking) - תהליך שבו הוא מפרק את הבעיה, מתכנן ובוחן כיוונים לפני שהוא כותב תשובה.

איפה משנים

  1. לוחצים על שם המודל ליד כפתור השליחה.
  2. בוחרים Effort ומשנים רמה: Low ו-Medium למשימות שגרתיות (חוסכים מכסה), High לאיזון איכות-מהירות, ו-xhigh ו-Max למשימות קוד ארוכות ומורכבות במיוחד.
  3. באותו תפריט מדליקים את הטוגל Thinking (במודלים בלי רמות מאמץ - טוגל Extended).

איך זה נראה בפועל

  • מופיע אינדיקטור Thinking עם טיימר שמראה כמה זמן קלוד מעבד.
  • מעל התשובה נפתח אזור Thinking ניתן להרחבה - שם רואים את סיכום דרך החשיבה. שווה להציץ כשצריך לוודא איך הוא הגיע למסקנה.
  • ברירת המחדל היא אדפטיבית: לכל מודל יש רמת מאמץ מומלצת (מסומנת Default), וקלוד מתאים את עומק החשיבה לבעיה.

מתי להעלות ומתי לא

  • כדאי: באג מסובך, תכנון ארכיטקטורה, ניתוח מסמך כבד, בעיה רב-שלבית.
  • לא כדאי: שאלות שגרה וכתיבה יומיומית - מאמץ גבוה אוכל את מכסת השימוש מהר יותר בלי תועלת.
  • שינוי הבוררים חל מהתשובה הבאה, ואפשר לשנות באמצע שיחה.
ברישיון ארגוני: האדמין יכול לקבוע רמת מאמץ ברירת-מחדל לסשנים של Claude Code (מדיניות effortLevel) ולהסתיר מודלים או רמות מסוימות. אם בורר שציפיתם לו חסר - כנראה שהוגבל ברמת הארגון.
סרטון דמו 10 - חשיבה מורחבת ורמת מאמץ (~3 דקות)
מקור: Model, effort, and thinking settings

סקירת קוד, דיפים ו-PR

קלוד כותב את הקוד - אבל אתם נשארים בעלי הבית עליו. ארבע הרגלים הופכים את הסקירה לחלק טבעי מהעבודה ולא למטלה בסוף.

1. סוקרים דיפים, לא סומכים בעיניים עצומות

  • כל עריכה מוצגת כדיף: מה הוסף, מה נמחק, באיזה קובץ.
  • /diff פותח צפייה אינטראקטיבית בכל השינויים הפתוחים ובדיפים לפי תור.
  • רוצים תיקון? כותבים הערה על השורה ושולחים - קלוד מתקן ומציג דיף חדש.

2. מבקשים מקלוד לסקור את עצמו

לפני קומיט, בקשו סקירה: קלוד בודק את השינויים מול קומפילציה, באגי לוגיקה ודאים ובעיות אבטחה - בלי להתפנק על סגנון שהלינטר תופס בכל מקרה. הסקיל המובנה /simplify עובר על הקבצים ששיניתם ומציע תיקוני איכות ושימוש-חוזר.

3. רואים את זה רץ

לבקש מקלוד להרים את האפליקציה מקומית ולבדוק שהיא באמת עובדת - הרבה מעבר ל"הקוד מתקמפל". הוא יודע להריץ, לקרוא שגיאות ולתקן לבד.

4. PR ו-CI

  • קלוד פותח PR דרך ה-CLI של GitHub ועוקב אחרי סטטוס הבדיקות.
  • בדיקה נכשלה? בקשו ממנו לקרוא את הלוג ולתקן - לולאת תיקון מלאה בלי לצאת מהסשן.

קיצורים וטיפים שחוסכים שעות

אוסף הקיצורים והטריקים שהופכים עבודה עם Claude Code מאיטית-וקצת-מסורבלת לשטופה. בתוך הסשן, הקשת ? מציגה את רשימת הקיצורים המדויקת לסביבה שלכם.

הקיצורים ששווה לשנן

  • Shift+Tab - מחליף מצב הרשאות (פרק 9).
  • Esc - עוצר את קלוד באמצע פעולה. Esc Esc - תפריט חזרה לצ'קפוינט (כמו /rewind).
  • Ctrl+R - חיפוש אחורה בהיסטוריית ההנחיות. חיצים גוללים בהיסטוריה.
  • Ctrl+O - תצוגת טרנסקריפט מלאה ומפורטת (verbose).
  • @ + נתיב - מוסיף קובץ או תיקייה להקשר של ההנחיה.
  • / - תפריט כל הפקודות הזמינות אצלכם, כולל סקילים וכלים מ-MCP.

פקודות קטנות, תועלת גדולה

  • /btw - שאלת צד שלא נכנסת לשיחה ולא צורכת קונטקסט.
  • /export - שומר את השיחה לקובץ או ללוח.
  • /status ו-/doctor - מה קורה בסשן, ואבחון בעיות התקנה.
  • /add-dir - נותן לקלוד גישה לתיקייה נוספת לסשן הזה.

שלושה טיפים שמשנים הרגלים

  1. הנחיה אחת מדויקת עם קובץ מצורף מנצחת חמש הנחיות מעורפלות.
  2. נתקעתם על התנהגות מוזרה? /clear ומתחילים נקי במקום להיאבק בהקשר מלוכלך.
  3. מתקן אחד בסשן: כשהוא מתחיל לתקן את התיקון של התיקון - עוצרים, חוזרים לצ'קפוינט, ונסחפים מחדש עם הוראה חדה יותר.

סקילים: ללמד את קלוד את הדרך שלכם

סקיל (Skill) הוא חבילת הוראות מסודרת - קובץ SKILL.md ולצידו קבצי עזר - שמלמדת את קלוד תהליך עבודה ספציפי: איך לייצר דוח, איך לבנות דשבורד, איך לעבוד מול Fabric. במקום לכתוב את אותן הוראות מחדש בכל שיחה - כותבים פעם אחת, וקלוד מפעיל את הסקיל כשרלוונטי.

איך סקיל בנוי

  • תיקייה עם קובץ SKILL.md: שם, תיאור קצר (לפיו קלוד מחליט מתי להפעיל), וההוראות עצמן.
  • לצידו אפשר לשים תבניות, דוגמאות וסקריפטים שהסקיל משתמש בהם.

התקנה בסביבה נעולה - בלי חנות, בלי פלאגינים

  1. ב-Claude Code (הדרך המומלצת בארגון): שמים את תיקיית הסקיל בתוך .claude/skills/ בפרויקט (או בתיקיית הבית לסקיל אישי גלובלי). קלוד מזהה אותו אוטומטית - בלי שוק, בלי התקנות.
  2. ב-Chat: מארזים את תיקיית הסקיל כ-ZIP ומעלים ב-Customize > Skills > Upload a skill. תלוי שהאדמין אישר סקילים בארגון.
  3. קיבלתם סקיל מצוות אחר? מספיק להעתיק את התיקייה למקום הנכון - זה כל ה"התקנה".

איך משתמשים

ברוב המקרים לא צריך לקרוא לסקיל בשם: קלוד מפעיל אותו אוטומטית כשהמשימה מתאימה לתיאור שלו. אפשר גם להפעיל ידנית עם / ושם הסקיל. רשימת הסקילים הזמינים מופיעה בפקודת הרשימה המתאימה (/ בתוך סשן Code).

פקודות סלאש: השלט המקומי של הסשן

כל מה שמתחיל ב-/ הוא פקודה: פעולות על הסשן עצמו - ניקוי, דחיסה, מעבר מצב, ניהול כלים. הקלדת / על שורה ריקה פותחת את הרשימה המלאה שזמינה אצלכם, כולל פקודות שמגיעות מסקילים ומשרתי MCP.

הפקודות שתשתמשו בהן הכי הרבה

  • /init - סורק את הקוד וכותב CLAUDE.md התחלתי לפרויקט (פרק 17).
  • /clear ו-/compact - ניהול קונטקסט (פרק 6).
  • /model - החלפת המודל הפעיל. /cost - צריכת הטוקנים בסשן.
  • /permissions - אילו כלים דורשים אישור (פרק 9). /plan - קפיצה ישר למצב Plan.
  • /agents - ניהול סאב-אייג'נטים (פרק 15). /hooks - צפייה בהוקס (פרק 16).
  • /mcp - ניהול חיבורי שרתי MCP (פרק 18). /memory - עריכת קבצי CLAUDE.md בטווח.
  • /help - כל הפקודות. /resume - חזרה לסשן קודם. /exit - יציאה.

פקודות מותאמות אישית

הצוות שלכם יכול להגדיר פקודות משלו כסקילים בתוך .claude/skills/ (הנתיב הישן .claude/commands/ עדיין עובד). ככה תהליך חוזר - "בדיקות לפני merge", "דוח ספרינט" - הופך לפקודה אחת שכולם מריצים אותה אותו דבר.

סאב-אייג'נטים: לפצל משימה גדולה נכון

בשיחה רגילה אתם מדברים עם הסוכן הראשי. כשהמשימה גדולה או ארוכה, הסוכן הראשי יכול להקים סאב-אייג'נטים - מופעי קלוד נוספים, כל אחד עם חלון הקשר משלו ומשימה ממוקדת משלו: להריץ בדיקות, לסרוק קודבייס גדול, לסקור קוד - ולדווח חזרה.

למה זה חזק

  • קונטקסט נקי: עבודת החיפוש הכבדה קורית בסשן המשני, והסשן הראשי מקבל רק את המסקנות - חלון ההקשר שלכם לא מתמלא בפסולת.
  • מקביליות: כמה סאב-אייג'נטים עובדים במקביל על חלקים שונים.
  • התמחות: אפשר להגדיר סאב-אייג'נט עם הוראות וכלים משלו - "סוקר אבטחה", "מומחה בדיקות".

איך עובדים איתם

  1. /agents מציג, יוצר ועורך סאב-אייג'נטים. ההגדרה נשמרת בקובץ בתוך .claude/agents/ בפרויקט - ולכן ניתנת לשיתוף בגיט עם הצוות.
  2. לא חייבים להגדיר מראש: תנו משימה מורכבת והסוכן הראשי יחליט לפצל בעצמו.
  3. רוצים לכפות? כתבו במפורש: "הרץ את הבדיקות בסאב-אייג'נט ותחזיר רק כשלונות".
כלל אצבע: משימה שדורשת סריקה רחבה אבל תשובה קצרה - מועמדת מושלמת לסאב-אייג'נט. הראשי נשאר חד, והדו"ח חוזר נקי.

הוקס: אוטומציה על נקודות החיים של הסשן

הוק (Hook) הוא פקודת מעטפת שרצה אוטומטית בנקודה מוגדרת במחזור החיים של הסשן - לפני שכלי רץ, אחרי עריכה, בתחילת סשן. זו הדרך להפוך כללי צוות לאכיפה אוטומטית: קלוד לא "זוכר" לעשות פורמט - ההוק דואג לזה.

שימושים קלאסיים

  • פורמט אוטומטי: אחרי כל עריכת קובץ, רץ prettier/black על הקובץ.
  • לינט ובדיקות: אחרי עריכה, בדיקה מהירה שתופסת שגיאות לפני שאתם רואים אותן.
  • מגן בטיחות: חסימת פקודות מסוכנות (למשל מחיקות רוחביות) לפני שהן רצות.
  • איתחול סשן: בתחילת סשן - טעינת משתני סביבה או בדיקת תלויות.

איך מגדירים

  1. הוקס מוגדרים בקבצי ההגדרות של הפרויקט (או האישיים) - אירוע, תנאי, והפקודה לריצה.
  2. /hooks בתוך סשן מציג את ההוקס הפעילים ולאיזה אירוע הם קשורים.
  3. הגדרות ב-.claude/ של הפרויקט נשמרות בגיט - כל הצוות מקבל אותן הוקס.
זהירות: הוק רץ על המחשב שלכם עם ההרשאות שלכם, בכל פעם שהאירוע קורה. כתבו הוקס קטנים, צפויים ומהירים - ואל תשימו בהם לוגיקה שאתם לא מבינים.

שגרות (Routines): אוטומציה על לוח זמנים

הוק מגיב לאירוע בתוך סשן; שגרה היא הגדרה שמורה - פרומפט, ריפו אחד או יותר, וקונקטורים - שרצה אוטומטית על לוח זמנים, מקריאת API או מאירוע GitHub (הפיצ׳ר ב-Research Preview). שגרות רצות על התשתית הענןית של Anthropic (או על סביבה מתארחת-עצמית של הארגון), כך שהן עובדות גם כשהמחשב שלכם סגור.

  • איפה: בעמוד claude.ai/code/routines, בלשונית Code באפליקציית הדסקטופ (Routines בסרגל הצד), או ב-CLI עם /schedule. זמין ב-Pro, Max, Team ו-Enterprise.
  • דוגמאות: סיכום Issues שנפתחו מאתמול כל בוקר עבודה, סקירת PR אוטומטית על כל pull_request, דיג׳סט מיילים יומי מתוזמן.
  • מגבלות: יש מכסת ריצות יומית לחשבון (ריצות חד-פעמיות לא נספרות); הצריכה יורדת ממכסת המנוי הרגילה. פעולות שהשגרה עושה דרך GitHub והקונקטורים מתועדות על שמכם.
  • שים לב: האפשרות "Local" בדסקטופ יוצרת Desktop scheduled task - משימה מקומית שרצה על המחשב שלכם (תכונה נפרדת, לא שגרת ענן).
בסביבה נעולה: האדמין יכול לכבות שגרות לכל הארגון (מתג Routines ב-admin settings) - אם האפשרות חסרה, כנראה שכבו אותה ברמת הארגון. וחשוב: שרתי MCP מקומיים שהוספתם ב-CLI לא זמינים לשגרות - הן רואות רק קונקטורים של חשבון claude.ai או שרתים שמוגדרים ב-.mcp.json בתוך הריפו. האלטרנטיבה המקומית: Desktop scheduled tasks, שרצות על המחשב שלכם עם גישה לקבצים מקומיים.

CLAUDE.md: הזיכרון הקבוע של הפרויקט

CLAUDE.md הוא קובץ מרקדאון שקלוד קורא אוטומטית בתחילת כל סשן. שם שמים את כל מה שלא רוצים לחזור עליו: מוסכמות הפרויקט, פקודות הבילד והבדיקה, אילוצים, ו"איך אנחנו עובדים כאן". זה ההבדל בין סוכן שמניח לבין סוכן שיודע.

איפה הקובץ חי

  • שורש הפרויקט - המקום המרכזי; נכנס לגיט ומשותף לצוות.
  • תיקיית הבית - העדפות אישיות שחלות על כל הפרויקטים שלכם.
  • תת-תיקיות - כללים לאזור ספציפי בקוד, מתווספים כשעובדים שם.

איך יוצרים ומה כותבים

  1. הדרך הקלה: /init - קלוד סורק את הפרויקט ומציע CLAUDE.md התחלתי. מכאן עורכים.
  2. כותבים קצר וקונקרטי: פקודות הבילד והטסט האמיתיות, קונבנציות שמות, "אל תיגע בתיקיית X", "כל PR דורש בדיקה Y".
  3. מעדכנים כשלומדים: קלוד טעה פעמיים באותה טעות? הופכים את התיקון לשורה ב-CLAUDE.md.
  4. /memory בתוך סשן פותח את קבצי ה-CLAUDE.md שבטווח לעריכה מהירה.
כלל אצבע: אם משפט לא יעזור למפתח חדש בצוות - הוא לא שייך ל-CLAUDE.md. הקובץ הטוב ביותר קצר, חד, ומתעדכן כל הזמן.

MCP: לחבר את קלוד למערכות שלכם - בעצמכם

MCP (Model Context Protocol) הוא תקן פתוח שמחבר את קלוד למערכות חיצוניות כלים: בסיסי נתונים, GitHub, Fabric, קבצים מקומיים, API פנימי של הארגון. ברישיון נעול אין ספריית קונקטורים - אז טוענים שרתי MCP בעצמכם, וזה פשוט יותר ממה שזה נשמע.

מה זה שרת MCP

תוכנית קטנה שרצה על המחשב שלכם (שרת מקומי, stdio) או שירות מרוחק, וחושפת לקלוד "כלים" - פעולות שהוא יכול להזמין: "קרא מה-DB", "צור דוח ב-Fabric". אחרי הטעינה, הכלים מופיעים בסשן כמו כל כלי אחר, עם אישורים לפי מצב ההרשאות.

טעינה ידנית - צעד אחר צעד

  1. ודאו שהאדמין מאפשר שרתי MCP מקומיים (מדיניות isLocalDevMcpEnabled - אצלכם זה פתוח, אחרת אין פרק).
  2. פתחו את קובץ ההגדרות: באפליקציית הדסקטופ - Settings, שם אזור ה-Developer ו-Edit Config, שפותח את claude_desktop_config.json.
  3. הוסיפו שרת תחת mcpServers - למשל שרת שמשרת קבצים:
    { "mcpServers": { "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "C:\\work\\data"] } } }
  4. שמרו והפעילו מחדש את האפליקציה לגמרי (יציאה מלאה, לא רק סגירת חלון).

איך מוודאים שזה עבד

  • בצ'אט: כפתור ה-+ > Connectors מציג את השרתים והכלים שזוהו.
  • בהגדרות Developer רואים סטטוס חיבור ולוגים לכל שרת.
  • ב-Claude Code: /mcp מנהל חיבורים ואימות.

כשלא עובד - הגורמים השכיחים בסביבה נעולה

  • רשת חסומה: שרת שמושך חבילות מהאינטרנט (npx) ייכשל מאחורי פרוקסי ארגוני - בקשו מ-IT התקנה מקומית של השרת ונתיב ישיר לקובץ ההרצה.
  • JSON שבור: פסיק מיותר או מרכאות חסרות - האפליקציה תתעלם מהקובץ בשקט. ודאו שהקובץ תקין.
  • Node/Python חסר: חלק מהשרתים דורשים סביבת הרצה. לשרתי Node בדסקטופ יש סביבה מובנית; בטרמינל - צריך התקנה (דרך IT).
  • לא הופעל מחדש: שינוי קונפיג תקף רק אחרי הפעלה מחדש מלאה.

Skills for Fabric: מה זה ואיך מתקינים בארגון נעול

Skills for Fabric הם סקילים בקוד פתוח (רישיון MIT, בריפו microsoft/skills-for-fabric) שמלמדים כלי קוד-AI - ובהם Claude Code - לעבוד מול Microsoft Fabric: אילו REST APIs לקרוא, איזה תחביר שאילתות, ואילו דפוסי עבודה נכונים. בלעדיהם לכלי ה-AI אין ידע מובנה על ה-APIs של Fabric.

הם עובדים הכי טוב ביחד: הסקיל מלמד, ה-MCP מחבר.

התקנה בארגון נעול - בלי מרקטפלייס, בלי פלאגינים

  1. מורידים את הריפו: git clone של microsoft/skills-for-fabric, או הורדת ZIP מדף הריפו (אם הרשת חוסמת - דרך עמדה מאושרת/IT).
  2. מעתיקים את תיקיות הסקילים הרלוונטיים אל .claude/skills/ בתיקיית הפרויקט שלכם. כל תיקיית סקיל מכילה SKILL.md - זה כל מה ש-Claude Code צריך.
  3. טוענים את שרת ה-Fabric MCP דרך קובץ ההגדרות, בדיוק כמו בפרק 18 - ה-MCP נותן גישה חיה, הסקילים נותנים את הידע.
  4. פותחים סשן בפרויקט ובודקים: הסקילים מופיעים ברשימת ה-/, והכלים של ה-MCP ב-/mcp.
הוראות ההתקנה הרשמיות מדברות על מרקטפלייס פלאגינים (/plugin install) - זה לא קיים ברישיון נעול. ההתקנה הידנית למעלה מביאה בדיוק את אותם סקילים, מאותו ריפו.

  • "בנה ארכיטקטורת medallion (Bronze/Silver/Gold) לדאטה שלי" ← יוצר lakehouses, notebooks ו-pipelines.
  • "הגדר Git integration ו-deployment pipeline ל-workspace".
  • "כתוב סמנטיק מודל מעל ה-Gold lakehouse שלי".
  • "תעד את כל ה-workspace שלי" ← סריקה ותיעוד Markdown.
גבול חשוב מהתיעוד: הסקילים מייצרים הגדרות פריטים וקוד - הם לא מרנדרים דוחות Power BI גמורים לבד. לוויזואליזציה: דשבורד Python מקומי, PDF, או בניית הדוח על הסמנטיק מודל (וסקילי הכתיבה בפרק הבא מכסים חלק מזה בפריוויו).

כתיבת דוחות Power BI עם AI (Preview): מהתכנון לפרסום

אוסף הסקילים AI-powered Power BI reporting (פריוויו, יוני 2026) מאפשר לסוכן AI לכתוב דוחות Power BI משפה טבעית: יצירה מאפס, שינוי דוח קיים, ומודרניזציה של עיצוב. זה חלק מספריית Skills for Fabric - ומתקינים אותו בדיוק כמו בפרק הקודם: העתקת תיקיות הסקילים ל-.claude/skills/ בפרויקט.

מה הסוכן עושה בפועל

  • כותב קבצי PBIR תקינים-סכמטית (הפורמט של פרויקטי PBIP) - דפים, ויז'ואלים, סלייסרים, טבלאות.
  • עובד עם ה-Desktop bridge: טוען מחדש את השינויים ב-Power BI Desktop הפתוח (בלי לסגור ולפתוח), מצלם מסך של הדפים, רואה את הפלט האמיתי ומתקן באיטרציות.
  • סקיל העיצוב (powerbi-report-design) מייצר "תדריך עיצוב" מסודר לפי עקרונות best practice - ואז מיישמים אותו.

דוגמת פרומפט שעובד (מהבלוג הרשמי)

"צור דוח עם דף Opportunities שיש בו ארבעה KPIs למדדים Revenue Won, Revenue in Pipeline... הוסף סלייסרים לרמות סיכון... והוסף דף Collabs עם ארבעה כרטיסי KPI..." - והסוכן בונה את הדפים.

האקוסיסטם המלא

סקילי הכתיבה עובדים יחד עם שרת ה-Modeling MCP וסקיל כתיבת הסמנטיק מודל (פרק 21): בונים מודל, ואז דוח מעליו, ואז מפרסמים ל-Fabric - מקצה לקצה.

שרת ה-Modeling MCP וכתיבת סמנטיק מודל עם AI

שרת ה-Power BI Modeling MCP נותן לכלי ה-AI גישה חיה לפעולות מידול: קריאה וכתיבה של הגדרות הסמנטיק מודל. בשילוב עם סקיל כתיבת המודל, הסוכן בונה מימדים, טבלאות עובדות וקשרים - ואתה סוקר לפני שמירה.

שימושים מתועדים

  • יצירת סמנטיק מודל מעל lakehouse בשפה טבעית.

  • Notebook עם אוסף utilities.
