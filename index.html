01

מה יש לכם ואיך המדריך עובד

המדריך הזה כתוב בשבילכם: עובדים עם רישיון ארגוני (Team/Enterprise) בסביבה נעולה. כל מה שתקראו כאן עובד בסביבה כזאת - בלי יוצא מן הכלל, בלי פיצ'רים שהאדמין חסם.

מה יש לכם

  • Claude Chat - השיחה הרגילה: שאלות, כתיבה, ניתוח מסמכים, פרויקטים וארטיפקטים. באפליקציית דסקטופ, בדפדפן ובמובייל.
  • Claude Code - סוכן הפיתוח: כותב, מריץ ובודק קוד על המחשב שלכם. עובד בטרמינל, בתוך אפליקציית הדסקטופ, וב-VS Code.
  • שרתי MCP שטוענים בעצמכם - חיבור של קלוד למערכות שלכם (קבצים, בסיסי נתונים, Fabric) דרך קובץ הגדרות פשוט. פרק 18 מדריך צעד-צעד.
  • סקילים מקבצים - חבילות הוראות שאתם יוצרים או מקבלים, ומעלים בעצמכם. פרק 13.

מתחילים: התקנה וכניסה

  1. מורידים את אפליקציית הדסקטופ מ-claude.com/download (Windows ו-Mac) - או עובדים בדפדפן ב-claude.ai.
  2. נכנסים עם מייל העבודה של הארגון. הרישיון מזוהה אוטומטית, והמסך שעולה זהה בדסקטופ ובדפדפן.
  3. מכאן כל הפרקים בחלק א׳ מתאימים לשניהם - אותם כפתורים, אותם מקומות.
מה שלא תראו ברישיון נעול - וזה תקין: Cowork (סוכן הענן), סשני ענן של Code, ספריית הקונקטורים וחנות הפלאגינים מושבתים אצל ארגונים רבים על ידי האדמין (באמצעות מדיניות כמו secureVmFeaturesEnabled ו-isDesktopExtensionDirectoryEnabled). אם נתקלתם במדריך אחר שמדבר עליהם - תדעו שהם קיימים, פשוט לא אצלכם. כל שאר המדריך לא תלוי בהם.

  2. חלק ב׳ (פרקים 7-12): Claude Code - התקנה, סשן ראשון, הרשאות וחשיבה מורחבת.

02

Chat: השיחה הראשונה

Chat הוא המקום שבו מתחילים: שיחה עם קלוד על כל דבר - שאלה, טיוטה, ניתוח קובץ, סיעור מוחות. כמה דקות של היכרות עם המסך חוסכות שעות בהמשך.

מה יש על המסך

  • סרגל צד: כפתור New לצ'אט חדש, ומתחתיו פרויקטים, ארטיפקטים והצ'אטים האחרונים.
  • תיבת ההודעה (הקומפוזר): כאן כותבים. ה-+ מצרף קבצים ותמונות, וגם פותח כלים: סקילים, חיפוש ברשת וזיכרון (פרק 5).
  • בורר המודל בתוך שורת הקומפוזר: בחירת מודל, רמת מאמץ (Effort) והדלקת חשיבה מורחבת - פרק 10 מתעמק.
  • הלשוניות Chat ו-Cowork מעל הקומפוזר: ברישיון נעול לשונית Cowork בדרך כלל מושבתת - נשארים ב-Chat.

השיחה הראשונה - איך עובדים נכון

  1. פתחו צ'אט חדש וכתבו בקשה אחת ברורה: מה רוצים, באיזה פורמט, ובשביל מי.
  2. צרפו חומר אמיתי עם ה-+ במקום לתאר אותו - מסמך, טבלה, צילום מסך.
  3. קיבלתם תשובה קרובה? הגיבו בתוך אותה שיחה מה לתקן. קלוד זוכר את ההקשר לאורך השיחה.
  4. נושא חדש? פתחו צ'אט חדש. שיחות ארוכות ומעורבבות פוגעות בדיוק (פרק 6).

מתי Chat ומתי Claude Code

כלל אצבע פשוט: אם התוצר הוא תשובה, מסמך או ניתוח - Chat. אם צריך לגעת בקבצים, להריץ פקודות או לבנות תוכנה - Claude Code (חלק ב׳). שניהם חלק מאותו מנוי ארגוני.

03

פרויקטים: בית קבוע לנושא חוזר

פרויקט ב-Chat הוא מרחב עבודה לנושא אחד שחוזר על עצמו: הוראות קבועות, קבצי רקע, וכל השיחות בנושא - במקום אחד. אם אתם חוזרים לאותו תחום שוב ושוב, פרויקט חוסך את ההקשר מחדש בכל פעם.

מתי פותחים פרויקט

  • דוח שבועי חוזר, לקוח קבוע, מסמך שמתעדכן - כל נושא עם הוראות וחומרים קבועים.
  • לא מתאים ל: שאלה חד-פעמית או נושא שמשתנה בכל שיחה.

איך בונים פרויקט שעובד

  1. יוצרים פרויקט חדש: שם ברור, ובשדה "What are you trying to achieve?" משפט אחד על המטרה.
  2. כותבים הוראות (Instructions) קצרות וקונקרטיות בפאנל הימני: מי הקהל, איזה טון, איזה פורמט פלט, מה אסור.
  3. מעלים קבצי רקע לפאנל Context שההוראות מפנות אליהם: דוגמאות, תבניות, מונחון. לכל פרויקט נבנה גם זיכרון משלו מהשיחות שבו.
  4. עובדים בתוך הפרויקט - כל שיחה חדשה בו כבר יודעת את ההקשר.

מלכודות נפוצות

  • הוראות ארוכות ומעורפלות עובדות פחות טוב מהוראות קצרות ומדויקות.
  • שיתוף פרויקט ("Can view" / "Can edit") זמין ברישיונות Team ו-Enterprise.
  • גם ב-Claude Code עובדים "לפי פרויקט", אבל שם הפרויקט הוא תיקיית העבודה על המחשב (עם קובץ CLAUDE.md משלה, פרק 17) - לא אותו פרויקט של Chat.

04

ארטיפקטים: תוצרים חיים, לא עוד תשובה בצ'אט

ארטיפקט הוא תוצר שנפתח לצד השיחה וחי חיים משלו: מסמך, טבלת קוד, ממשק קטן או דשבורד אינטראקטיבי. במקום לקבל את התשובה כטקסט בזרם הצ'אט - מקבלים דבר שאפשר לערוך, לשכלל ולשתף.

מתי קלוד יוצר ארטיפקט

  • תוכן שעומד בפני עצמו: מסמך, דוח, מצגת, רכיב קוד, טבלה גדולה.
  • דבר שתרצו לערוך שוב ושוב - כל בקשת תיקון מעדכנת את אותו ארטיפקט.

איך עובדים איתו

  1. מבקשים תוצר ("תכין דוח מסכם", "תבנה דשבורד קטן מהקובץ") - הארטיפקט נפתח בפאנל שמצד השיחה ומתרנדר מיד.
  2. משכללים בשיחה: "תוסיף עמודת סה״כ", "תשנה את הכותרת" - אותו ארטיפקט מתעדכן מחדש.
  3. כל הארטיפקטים נשמרים בעמוד Artifacts בסרגל הצד - אפשר לחזור אליהם, לשתף או להוריד בכל זמן.

טיפ שחוסך זמן

אם קיבלתם טקסט ארוך בתוך הצ'אט במקום ארטיפקט - פשוט בקשו: "תהפוך את זה לארטיפקט". זו הדרך המהירה להעביר תוצר למסלול עריכה נכון.

05

זיכרון, חיפוש ואינקוגניטו

שלושה מנגנונים שולטים במה שקלוד זוכר עליכם - ומתי הוא דווקא לא זוכר כלום. בשליטה שלכם, ובשלוש דקות מבינים את כל התמונה.

זיכרון: מה קלוד יודע עליכם

  1. קלוד מזהה נושאים חוזרים בשיחות שלכם (תפקיד, העדפות, פרויקטים) ושומר אותם כרשימת נושאים.
  2. פתחו Settings ← Memory ותראו בעצמכם: מתג "Generate memory from chats", רשימת הנושאים, ושדה שבו כותבים לקלוד מה לשנות או למחוק. הכל ניתן לעריכה או מחיקה מלאה.
  3. כלל אצבע ארגוני: מידע רגיש שלא הייתם רושמים לעצמכם בפתק - אל תכניסו לזיכרון.

חיפוש: ברשת ובשיחות עבר

שני חיפושים שכדאי להכיר. חיפוש ברשת: בתפריט ה-+ אפשר להדליק או לכבות Web search לכל שיחה - כשזה דולק, קלוד שולף מידע עדכני מהאינטרנט עם מקורות. חיפוש בשיחות עבר: שואלים בשפה טבעית ("מה החלטנו על המחירון של רבע 4?") וקלוד שולף את ההקשר מהשיחה הרלוונטית - אין צורך לזכור איפה זה נכתב.

אינקוגניטו: שיחה שלא נשמרת

צ'אט אינקוגניטו מתחיל מכפתור Use incognito (אייקון הרפאים) בראש מסך הצ'אט. שיחה כזאת נשארת מחוץ להיסטוריה, לזיכרון ולחיפוש, ולא משמשת לאימון המודל. מתאים לניסוי חד-פעמי, שאלה אישית, או טיוטה שלא צריכה להשאיר עקבות. שימו לב: ברישיון ארגוני המדיניות של הארגון חלה גם כאן.

06

קונטקסט וטוקנים: זיכרון העבודה של קלוד

לכל שיחה יש "חלון הקשר" - כמות המידע המקסימלית שקלוד מחזיק בראש ברגע נתון: ההוראות, הכלים, ההודעות ותוצאות הכלים. כשהחלון מתמלא, הביצועים יורדים. מי שמנהל את החלון נכון - מקבל תשובות טובות יותר.

אנימציית הסבר: חלון הקונטקסט מתמלא - ואיך /compact מפנה מקום (22 שניות)

ב-Chat: לעקוב ולפצל בזמן

  • מד השימוש בתפריט המודל מראה כמה מהחלון נוצל בשיחה הנוכחית (Low usage ומעלה).
  • שיחה שהתארכה מאוד? בקשו מקלוד סיכום של מה שהושג, ופתחו צ'אט חדש עם הסיכום. זה ה-/compact הידני שלכם בצ'אט.
  • בצ'אט אין פקודות דחיסה - הניהול הידני המלא (בפקודות) קיים ב-Claude Code, כאן למטה.

ב-Claude Code: שלוש פקודות ששוות זהב

  • /context - מציג מה טוען את חלון ההקשר כרגע ואיפה התקציב הולך.
  • /compact - סיכום השיחה לשחרור מקום, אפשר עם הוראות מיקוד.
  • /clear - מנקה את היסטוריית השיחה לגמרי (זיכרון הפרויקט נשמר). לפתיחת נושא חדש.

חמישה כללי עבודה

  1. שיחה חדשה לנושא חדש - הכלל החשוב מכולם.
  2. תנו לקלוד למשוך קבצים בעצמו במקום להדביק תוכן ענק לתוך הצ'אט.
  3. משימה ענקית? חלקו לשלבים, דחסו ביניהם.
  4. מסמך שחוזרים אליו הרבה? שימו אותו בפרויקט במקום בכל שיחה מחדש.
  5. מד השימוש עולה? זמן לסכם ולפצל.

Claude Code: מה זה, התקנה והגדרה

Claude Code הוא סוכן הפיתוח של קלוד: הוא קורא וכותב קבצים על המחשב שלכם, מריץ פקודות, בודק תוצאות ומתקן את עצמו. בניגוד ל-Chat שמחזיר תשובה - Code מבצע עבודה מקצה לקצה בתוך הפרויקט שלכם.

איפה הוא רץ

  • אפליקציית הדסקטופ: לשונית Code - הדרך הכי נוחה להתחיל, הכל בתוך האפליקציה שכבר יש לכם.
  • טרמינל: מריצים claude בתיקיית הפרויקט. הדרך הקלאסית של מפתחים.
  • VS Code: הרחבה רשמית שמחברת את הסשן לעורך - רואים דיפים ועריכות בתוך ה-IDE.

התקנה ברישיון ארגוני

  1. ודאו שיש לכם גישה: ברוב ארגוני ה-Team/Enterprise הזיכיון כולל Claude Code (בארגונים ישנים - תלוי בסוג המושב).
  2. דרך אפליקציית הדסקטופ: התקינו את האפליקציה והתחברו עם חשבון הארגון - לשונית Code מחכה בפנים.
  3. דרך הטרמינל: עקבו אחר הוראות ההתקנה הרשמיות לסביבה שלכם, והתחברו עם חשבון הארגון בהפעלה הראשונה. אל תריצו התקנה עם sudo - זה שובר הרשאות קבצים בהמשך.
בסביבה נעולה: אם ההתקנה נחסמת (אין הרשאות אדמין, רשת חוסמת, מדיניות MDM) - זה לא כשל שלכם. פנו ל-IT ובקשו התקנה מאושרת של Claude Desktop ו-Claude Code; האדמין שולט בזמינות דרך מדיניות (isClaudeCodeForDesktopEnabled). גם התקנת VS Code עצמו דורשת אישור IT ברוב הארגונים.

VS Code כסביבת העבודה

מומלץ לעבוד עם עורך קוד לצד הסוכן: VS Code הוא הבחירה הנפוצה, וההרחבה של Claude Code מציגה את הדיפים והעריכות ישירות בעורך. לא חובה - אפשר לעבוד גם מהדסקטופ או הטרמינל בלבד - אבל עם עורך הסקירה נוחה יותר.

08

סשנים, סביבות והפרויקט הראשון

כל שיחה ב-Claude Code היא סשן: היסטוריה משלה, תיקיית פרויקט משלה, שינויי קוד משלם. אפשר להחזיק כמה סשנים במקביל מהסרגל, ו-Cmd+N פותח סשן חדש.

הפרויקט הראשון שלכם - צעד אחר צעד

  1. צרו תיקייה חדשה למשימה (למשל expenses-board) ושימו בתוכה את קובץ הנתונים - נגיד קובץ אקסל של הוצאות.
  2. פתחו סשן בתיקייה הזו (מלשונית Code בדסקטופ, או claude מהטרמינל בתוך התיקייה).
  3. תנו הנחיה מדויקת: מה לבנות, מאיזה קובץ לקחת את הנתונים, ואיך התוצאה צריכה להיראות. "בנה דשבורד HTML שמסכם את ההוצאות מהקובץ, מחולק לקטגוריות, עם גרף חודשי" עובד הרבה יותר טוב מ"תעשה משהו עם האקסל".
  4. עקבו אחרי הפעולות שהוא מבצע, אשרו את מה שדורש אישור, ובקשו תיקונים בשיחה - "תוסיף סינון לפי חודש", "תשנה צבעים". ככה נראית עבודה נכונה: איטרציות קטנות, לא ניסיון אחד ענק.

עבודה מקבילה נכונה

  • כל סשן עובד על עותק מבודד של הריפו (worktree) - שני סשנים לא דורסים אחד את השני.
  • Cmd+; פותח שאלת צד: רואה את ההקשר בלי לגעת בשיחה הראשית (שקול ל-/btw בטרמינל).
  • ארכיון סשן תמיד מבקש אישור, ומתקבלת התראה כשסשן מסיים.
  • /resume (או /continue) פותח סשן קודם וממשיך מאותה נקודה.

פיצול המסך: צ'אט, טרמינל וקבצים זה לצד זה

  • סמל הטרמינל בראש הסשן פותח טרמינל אמיתי בצד המסך - מריצים פקודות ורואים פלט בלי לצאת מהאפליקציה. כפתור + מוסיף לשוניות טרמינל נוספות.
  • Ctrl+Shift+F פותח את רשימת קבצי הפרויקט, ולחיצה על קובץ פותחת אותו בחלונית צפייה ועריכה - לצד השיחה והטרמינל.
  • סמל הענף מציג את עץ העבודה (working tree) - כל השינויים שהסשן עשה בקוד, במבט אחד.
  • את גודל החלוניות משנים בגרירת המפריד ביניהן, ואייקון ההגדלה בכותרת החלונית מרחיב אותה לכל רוחב המסך.

תצוגה מפוצלת: שני סשנים באותו חלון. מעבר לחלוניות הטרמינל והקבצים, אפשר לפצל את החלון לשני סשנים מלאים זה לצד זה - כל אחד עם תיקיית הפרויקט וההיסטוריה שלו. Alt+Ctrl+\ פותח סשן חדש מימין (וגם למטה עם Alt+Ctrl+-), Ctrl+[ ו-Ctrl+] מעבירים את המיקוד בין החלוניות, ו-Alt+Ctrl+W סוגר את החלונית הנוכחית. שני הסשנים רצים במקביל בלי להפריע אחד לשני.

  2. סוקרים, מתקנים את התוכנית, מאשרים.
  3. עוברים ל-Accept edits לביצוע, ועוקבים.
  4. משהו השתבש? Esc עוצר מיד, ו-Esc Esc (או /rewind) מחזיר לצ'קפוינט קודם.

חשיבה מורחבת ורמת מאמץ

לפני שקלוד עונה, אפשר בהרבה חשבונות לשלוט בשני בוררים: כמה מאמץ (Effort) הוא משקיע בתשובה, והאם הוא עובר חשיבה מורחבת (Extended Thinking) - תהליך שבו הוא מפרק את הבעיה, מתכנן ובוחן כיוונים לפני שהוא כותב תשובה. הזמינות המדויקת של הבוררים תלויה במודל, בסוג החשבון ובמדיניות הארגון.

איפה משנים

  1. לוחצים על שם המודל ליד כפתור השליחה, ונפתח תפריט המודלים.
  2. בחשבונות שבהם הבוררים זמינים, באותו אזור מופיעים גם בחירת Effort (למשל Low, Medium, High) ומתג Thinking או Extended. שני הבוררים נפרדים: המאמץ קובע כמה יסודי קלוד יהיה בכל תשובה, והמתג קובע אם יופיע אזור חשיבה ניתן להרחבה.
  3. בסביבת ההדגמה כאן התפריט מציג את שמות המודלים בלבד - בלי בורר מאמץ ובלי מתג חשיבה - ולכן גם בסרטון אין שינוי שלהם.

איך זה נראה בפועל

  • כשנותנים משימה ל-Code, מתחת לפעולות מופיע מצב עבודה עם זמן שחלף, ולעיתים גם אזור שמסכם את התכנון או את הבדיקות שהסוכן מבצע - אבל זה לא חשיפה מלאה של תהליך החשיבה הפנימי שלו.
  • כשמתג ה-Thinking זמין ומופעל, נפתח מעל התשובה אזור Thinking ניתן להרחבה עם סיכום דרך החשיבה - שווה להציץ כשרוצים לוודא איך הוא הגיע למסקנה.
  • בחשבונות רבים ברירת המחדל אדפטיבית: לכל מודל יש רמת מאמץ מומלצת, וקלוד מתאים את עומק החשיבה לבעיה.

מתי להעלות ומתי לא

  • כדאי: באג מסובך, תכנון ארכיטקטורה, ניתוח מסמך כבד, בעיה רב-שלבית.
  • לא כדאי: שאלות שגרה וכתיבה יומיומית - מאמץ גבוה אוכל את מכסת השימוש מהר יותר בלי תועלת.
  • בחשבונות שבהם הבוררים זמינים, השינוי חל מהתשובה הבאה ואפשר לשנות באמצע שיחה.
ברישיון ארגוני: האדמין יכול לקבוע רמת מאמץ ברירת-מחדל לסשנים של Claude Code (מדיניות effortLevel) ולהסתיר מודלים או רמות מסוימות. אם בורר שציפיתם לו חסר - כנראה שהוגבל ברמת הארגון.

12

קיצורים וטיפים שחוסכים שעות

אוסף הקיצורים והטריקים שהופכים עבודה עם Claude Code מאיטית-וקצת-מסורבלת לשטופה. בתוך הסשן, הקשת ? מציגה את רשימת הקיצורים המדויקת לסביבה שלכם.

הקיצורים ששווה לשנן

  • Shift+Tab - מחליף מצב הרשאות (פרק 9).
  • Esc - עוצר את קלוד באמצע פעולה. Esc Esc - תפריט חזרה לצ'קפוינט (כמו /rewind).
  • Ctrl+R - חיפוש אחורה בהיסטוריית ההנחיות. חיצים גוללים בהיסטוריה.
  • Ctrl+O - תצוגת טרנסקריפט מלאה ומפורטת (verbose).
  • @ + נתיב - מוסיף קובץ או תיקייה להקשר של ההנחיה.

סקילים: ללמד את קלוד את הדרך שלכם

סקיל (Skill) הוא חבילת הוראות מסודרת - קובץ SKILL.md ולצידו קבצי עזר - שמלמדת את קלוד תהליך עבודה ספציפי: איך לייצר דוח, איך לבנות דשבורד, איך לעבוד מול Fabric. במקום לכתוב את אותן הוראות מחדש בכל שיחה - כותבים פעם אחת, וקלוד מפעיל את הסקיל כשרלוונטי.

סאב-אייג'נטים: לפצל משימה גדולה נכון

בשיחה רגילה אתם מדברים עם הסוכן הראשי. כשהמשימה גדולה או ארוכה, הסוכן הראשי יכול להקים סאב-אייג'נטים - מופעי קלוד נוספים, שכל אחד מהם מקבל חלון הקשר נקי משלו ומשימה ממוקדת משלו: לסרוק קודבייס ענק, לסקור מסמך משלוש נקודות מבט במקביל, להריץ בדיקות - ולדווח חזרה. הסוכן הראשי הוא התזמורת: הוא מפצל, הם עובדים, והוא מחזיר לכם תשובה אחת מאוחדת.

למה זה חזק

  • קונטקסט נקי: הסריקה הכבדה קורית בסשן המשני. עשרות אלפי טוקנים של קריאת קבצים נשארים שם - והסשן הראשי מקבל רק סיכום אחד. חלון ההקשר שלכם לא מתמלא בפסולת.
  • מקביליות: כמה סאב-אייג'נטים רצים באותו זמן על חלקים בלתי תלויים - למשל שלושה סוקרים עם פרסונות שונות על אותו מסמך.
  • התמחות ועלות: לכל סאב-אייג'נט אפשר להגדיר הוראות, כלים ומודל משלו - למשל סוכן ראשי חכם שמפקח על סוכני משנה זולים יותר.

איך יוצרים סאב-אייג'נט משלכם

  1. בשפה טבעית: מבקשים מהסוכן הראשי - "צור סאב-אייג'נט בשם code-reviewer שבודק..." - והוא יוצר את הקובץ. שימו לב: אשף ה-/agents הוסר מהממשק (בדקנו) - הדרכים הן בקשה בשפה טבעית או עריכה ידנית של הקובץ.
  2. ישירות בקובץ: קובץ Markdown בתוך .claude/agents/ בפרויקט (אפשר לשתף בגיט עם הצוות) או ~/.claude/agents/ (זמין בכל הפרויקטים שלכם).
  3. מה יש בקובץ: שם, תיאור (הטריגר - לפיו קלוד מחליט מתי להפעיל; עד שהסוכן מופעל, רק השם והתיאור תופסים מקום בקונטקסט), כלים מותרים, ומודל. רוצים סוכן קריאה-בלבד? מגבילים את הכלים (Read, Grep) - הגבלת כלים היא שכבת הרשאות אמיתית, חזקה הרבה יותר מ"בבקשה אל תערוך".

איך מפעילים

ברוב המקרים לא צריך לעשות כלום: הסוכן הראשי מפעיל את הסאב-אייג'נט המתאים לפי התיאור שלו. אפשר גם לקרוא לו בשם ("השתמש ב-docs-auditor") או לכפות פיצול ("הרץ את הבדיקות בסאב-אייג'נט והחזר רק כשלונות"). בממשק הנוכחי סאב-אייג'נטים רצים כמשימות רקע - רואים צ'יפ נפרד לכל אחד ומונה של משימות פעילות - כך שאפשר להפעיל כמה במקביל ולעקוב אחרי כולם. מלבד הסוכנים המובנים (כמו Explore ו-Plan) יפעלו גם הסוכנים שהגדרתם. אם סוכן לא נורה כשצריך - או נורה יתר על המידה - מכווננים את התיאור שלו.

מתי כן ומתי לא

  • כן: סריקה רחבה עם תשובה קצרה, עבודה חוזרת, משימות מקבילות בלתי תלויות, סקירה ניטרלית בעיניים טריות.
  • לא: עריכות קטנות, צעדים שתלויים זה בזה, משימה שצריכה את מלוא הקונטקסט של השיחה.

סקיל או סאב-אייג'נט?

שניהם קבצי Markdown עם frontmatter, וקל להתבלבל - אבל הם פותרים בעיות שונות: סקיל (פרק 13) מזריק ידע ותהליך עבודה לתוך הסשן שלכם - הוא רץ בקונטקסט שלכם וחולק אותו. סאב-אייג'נט מקבל קונטקסט נקי משלו, יכול לרוץ במקביל ועם מודל אחר - ומחזיר רק תוצאה. והם משלימים זה את זה: סקיל יכול להפעיל סאב-אייג'נטים, וסאב-אייג'נט יכול להשתמש בסקילים.

בטיחות: קובץ סוכן שהורדתם מהרשת הוא לכל דבר קוד שרץ אצלכם - ההוראות בו יכולות להכיל הזרקת פרומפט זדונית. קראו את הקובץ לפני ההתקנה, בדיוק כמו שקוראים סקריפט לפני שמריצים.
כלל אצבע: משימה שדורשת סריקה רחבה אבל תשובה קצרה - מועמדת מושלמת לסאב-אייג'נט. ועוד גבול שכדאי להכיר: סאב-אייג'נטים לא מדברים אחד עם השני - כל אחד מדווח רק לסוכן הראשי (תקשורת בין סוכנים היא כבר agent teams, נושא אחר).

הוקס: אוטומציה על נקודות החיים של הסשן

הוק (Hook) הוא פקודת מעטפת שרצה אוטומטית בנקודה מוגדרת במחזור החיים של הסשן - לפני שכלי רץ, אחרי עריכה, בתחילת סשן. זו הדרך להפוך כללי צוות לאכיפה אוטומטית: קלוד לא "זוכר" לעשות פורמט - ההוק דואג לזה.

שימושים קלאסיים

  • פורמט אוטומטי: אחרי כל עריכת קובץ, רץ prettier/black על הקובץ.
  • לינט ובדיקות: אחרי עריכה, בדיקה מהירה שתופסת שגיאות לפני שאתם רואים אותן.
  • מגן בטיחות: חסימת פקודות מסוכנות (למשל מחיקות רוחביות) לפני שהן רצות.
  • איתחול סשן: בתחילת סשן - טעינת משתני סביבה או בדיקת תלויות.

איך מגדירים

  1. הוקס מוגדרים בקבצי ההגדרות של הפרויקט (או האישיים) - אירוע, תנאי, והפקודה לריצה.
  2. ברגע שההגדרות במקום - ההוקס פועלים לבד: אין פקודה שמנהלת אותם מתוך הסשן, אבל רואים אותם בפעולה. בהדגמה למטה הוק PostToolUse כותב שורה ללוג אחרי כל עריכה, והוק PreToolUse חוסם ניסיון push ישיר.

MCP: לחבר את קלוד למערכות שלכם - בעצמכם

MCP (Model Context Protocol) הוא תקן פתוח שמחבר את קלוד למערכות חיצוניות כלים: בסיסי נתונים, GitHub, Fabric, קבצים מקומיים, API פנימי של הארגון. ברישיון נעול אין ספריית קונקטורים - אז טוענים שרתי MCP בעצמכם, וזה פשוט יותר ממה שזה נשמע.

אנימציית הסבר: קובץ הגדרות אחד מחבר את קלוד למערכות - והכלים מופיעים בסשן (19 שניות)

מה זה שרת MCP

תוכנית קטנה שרצה על המחשב שלכם (שרת מקומי, stdio) או שירות מרוחק, וחושפת לקלוד "כלים" - פעולות שהוא יכול להזמין: "קרא מה-DB", "צור דוח ב-Fabric". אחרי הטעינה, הכלים מופיעים בסשן כמו כל כלי אחר, עם אישורים לפי מצב ההרשאות.

טעינה ידנית - צעד אחר צעד

  1. ודאו שהאדמין מאפשר שרתי MCP מקומיים (מדיניות isLocalDevMcpEnabled - אצלכם זה פתוח, אחרת אין פרק).
  2. פתחו את קובץ ההגדרות: באפליקציית הדסקטופ - Settings, שם אזור ה-Developer ו-Edit Config, שפותח את claude_desktop_config.json.
  3. הוסיפו שרת תחת mcpServers - למשל שרת שמשרת קבצים:
    { "mcpServers": { "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "C:\\work\\data"] } } }
  4. שמרו והפעילו מחדש את האפליקציה לגמרי (יציאה מלאה, לא רק סגירת חלון).

איך מוודאים שזה עבד

  • בצ'אט: כפתור ה-+ > Connectors מציג את השרתים והכלים שזוהו.
  • בהגדרות Developer רואים סטטוס חיבור ולוגים לכל שרת.
  • ב-Claude Code: /mcp מנהל חיבורים ואימות.

כשלא עובד - הגורמים השכיחים בסביבה נעולה

  • רשת חסומה: שרת שמושך חבילות מהאינטרנט (npx) ייכשל מאחורי פרוקסי ארגוני - בקשו מ-IT התקנה מקומית של השרת ונתיב ישיר לקובץ ההרצה.
  • JSON שבור: פסיק מיותר או מרכאות חסרות - האפליקציה תתעלם מהקובץ בשקט. ודאו שהקובץ תקין.
  • Node/Python חסר: חלק מהשרתים דורשים סביבת הרצה. לשרתי Node בדסקטופ יש סביבה מובנית; בטרמינל - צריך התקנה (דרך IT).
  • לא הופעל מחדש: שינוי קונפיג תקף רק אחרי הפעלה מחדש מלאה.
  • תאימות גרסת השרת: גרסה חדשה של שרת עלולה לא לעבוד מול האפליקציה המותקנת - עדכנו את האפליקציה, או התקינו את השרת מקומית והפנו את ה-config ישירות לקובץ ההרצה.
  • תיקיית הסשן: האפליקציה מעבירה לשרת את תיקיית הפרויקט של הסשן בתור roots, ושרתי filesystem משרתים אותה במקום התיקייה שבקונפיג - פתחו את הסשן בתוך התיקייה שרוצים לשרת.

Mods: לשנות את Claude Code מבפנים

Mod הוא פונקציית TypeScript או JavaScript קטנה שרצה בתוך Claude Code עצמו ומגיבה לאירועים: קריאת כלי, שליחת פרומפט, בקשת הרשאה, ציור חלק מהמסך. היא יכולה לראות את האירוע, לשנות אותו, או להחליף אותו. Anthropic הכריזה על Mods ב-1 באוקטובר 2026, והם זמינים מגרסה 2.1.287 של Claude Code, ב-CLI וב-Code tab של אפליקציית הדסקטופ.

איך זה שונה ממה שכבר למדתם: הוק (פרק 16) הוא פקודת מעטפת שמוגדרת בקובץ הגדרות, רצה מחוץ ל-Claude Code ויכולה בעיקר להגיב. Mod רץ בתוך התהליך, ולכן יכול גם לשכתב פרומפט לפני שהוא מגיע למודל, לצייר חלונית וכפתורים, ולהחליף חלקים מהממשק. סקיל נותן לקלוד הוראות, ו-MCP נותן לו כלים. Mod משנה את Claude Code עצמו.

מה אפשר לעשות עם Mod

  • שער בטיחות: לעצור פקודה מסוכנת (כמו rm -rf או force push), להציג מה היא תשנה, ולתת כפתורי "המשך" ו"בטל".
  • הסתרת סודות: לנקות מפתחות וסיסמאות מפלט של כלי לפני שקלוד קורא אותו.
  • אישור או דחייה של הרשאות לפי כללים שלכם, ושכתוב או ניסיון חוזר של קריאת כלי.
  • ממשק משלכם: חלונית ליד השיחה, למשל מצב צינור הבנייה, או תחזית של מילוי חלון ההקשר.
  • פקודת / משלכם שמריצה פונקציה מיד, בלי תור של קלוד.

איך משתמשים בפועל

  1. בודקים גרסה: claude --version חייב להראות 2.1.287 ומעלה. Mods פעילים כברירת מחדל.
  2. מתקינים: Mod מגיע בתוך plugin. מתקינים עם /plugin install שם@marketplace בתוך הסשן, או claude plugin install שם@marketplace במעטפת. אחרי התקנה מהמעטפת בסשן פתוח: /reload-plugins.
  3. מנסים בלי להתקין: טוענים תיקייה לסשן אחד עם claude --plugin-dir ./שם-התיקייה. לדוגמה, Anthropic מפרסמת דוגמאות (blast-radius, token-weather, replay-theater) בריפו claude-code-playground, בלי תמיכה.
  4. בודקים שנטען: מריצים /plugin. שורה עמומה מתחת ללשוניות מציגה, למשל, "1 mod active".
  5. לפני שסומכים על Mod של מישהו אחר: מורידים את הקבצים ומריצים claude plugin validate ./תיקייה. השורות hooks: ו-calls: בפלט מפרטות על אילו אירועים הוא מגיב ומה הוא מבקש לעשות.

פרומפטים להעתקה

אפשר לבקש מקלוד לכתוב Mod: הוא כותב את הקוד, מתקין אותו וטוען אותו מחדש בסשן.

כתוב לי mod ל-Claude Code שמציג ליד הספינר כמה קריאות כלי בוצעו בתור הנוכחי. תסביר לי בשפה פשוטה אילו אירועים הוא מאזין להם ומה הוא ניגש אליו.

כתוב mod שמחזיק כל פקודת Bash שמכילה rm -rf או git push --force, ומציג לי כפתורי המשך וביטול לפני שהיא רצה.

לפני שאני מתקין את ה-mod הזה: הרץ claude plugin validate על התיקייה והסבר לי מה ה-hooks וה-calls אומרים, ומה ה-mod הזה יכול לראות ולעשות במחשב שלי.

פלט צפוי

  • אחרי הפרומפט הראשון: קלוד יוצר בדרך כלל תיקייה עם שלושה קבצים (.claude-plugin/plugin.json, hooks/hooks.json, hooks/register.js), טוען אותה, ובספינר מופיע טקסט דומה ל- Thinking · tool calls: 3….
  • אחרי השני: פקודה מסוכנת נעצרת, ואתם רואים מה היא תשנה לפני שמאשרים.
  • אחרי השלישי: רשימת האירועים והקריאות של ה-mod, וסיכום של מה הוא יכול לגעת בו.

תרגיל

  1. בתיקיית ניסוי (לא בפרויקט אמיתי), בקשו מקלוד את ה-mod הראשון, וודאו ב-/plugin שהוא נטען.
  2. בקשו מקלוד לקרוא כמה קבצים בתיקייה, ובדקו שהמונה בספינר עולה.
  3. כבו אותו: בלשונית Installed ב-/plugin. מה קרה לספינר? בדקו גם שבהפעלה עם --safe-mode הוא לא נטען.
בטיחות: Mod רץ עם אותן הרשאות כמו Claude Code: הוא יכול לקרוא ולכתוב קבצים, להפעיל תוכנות, לגשת לרשת, לקרוא משתני סביבה וקבצי הגדרות (כולל מפתח API), לראות כל פרומפט וכל קריאת כלי, ואפילו לאשר קריאת כלי לפני שנשאלתם. הוא לא בארגז חול. התקינו Mods רק ממקורות שאתם סומכים עליהם, כמו כל קוד אחר.

בסביבה נעולה (ארגון)

Mods מגיעים בתוך plugins, ובארגון שלכם אין פלאגינים. לכן כרגע אי אפשר להניח שהפיצ׳ר זמין לכם. מה שאומר התיעוד הרשמי, ומה שלא נבדק:

  • מה שהתיעוד אומר: אדמין שולט ב-Mods דרך אותן בקרות של plugins ודרך הגדרות מנוהלות. ב-Team וב-Enterprise נטען ראשון mod מובנה בשם sec-default שמונע מ-Mods של משתמשים לעקוף כללי deny של הארגון או לשנות הוקס מנוהלים. עם האפשרות allowManagedModsOnly הארגון יכול לחסום לגמרי Mods שהמשתמשים מביאים, כולל כאלה שנטענו עם --plugin-dir.
  • מה שלא נבדק אצלכם: אם מדיניות הארגון חוסמת רק את חנות הפלאגינים, או גם טעינה מקומית עם --plugin-dir. אל תנסו לעקוף את זה. שאלו את ה-IT: "האם Mods של Claude Code מותרים אצלנו, ובאיזה מסלול?"
  • אם מותר: Mods יכולים לתת לצוות שלכם דברים כמו חלונית סטטוס, אישור לפני פקודות על קונפיגורציית ייצור, ו-audit log של כל מה ש-Mods אחרים עושים.

Skills for Fabric: סקילי ה-Power BI - התקנה ישירה מגיטהאב, בלי Node

Skills for Fabric הם סקילים בקוד פתוח (רישיון MIT, בריפו microsoft/skills-for-fabric) שמלמדים כלי קוד-AI - ובהם Claude Code - לעבוד מול Microsoft Fabric ו-Power BI. הריפו מכסה את כל עומסי העבודה של Fabric; במדריך הזה מעניינים אותנו רק סקילי ה-Power BI: חבילת powerbi-authoring עם שני סקילים - semantic-model-authoring (כתיבת סמנטיק מודל) ו-powerbi-report-cli (כתיבת דוחות). בלעדיהם לכלי ה-AI אין ידע מובנה ב-APIs של Fabric ובפורמטים של Power BI.

התקנה בלי Node - ישירות מגיטהאב לתיקיית הפרויקט

סקיל הוא תיקיית Markdown בלבד, ולכן לא צריך Node, לא צריך מרקטפלייס, ולא צריך כלי התקנה:

  1. מורידים את הריפו: בדף github.com/microsoft/skills-for-fabric לוחצים על כפתור Code הירוק ← Download ZIP (או git clone אם git מותר ברשת). הרשת חוסמת? מורידים בעמדה מאושרת ומעבירים דרך IT.
  2. בתוך הקבצים שחולצו נכנסים ל-plugins/powerbi-authoring/skills/ - שם יושבים שני הסקילים.
  3. מעתיקים את התיקיות semantic-model-authoring ו-powerbi-report-cli אל .claude/skills/ בתיקיית הפרויקט שלכם. כל תיקיית סקיל מכילה SKILL.md - זה כל מה ש-Claude Code צריך.
  4. פותחים סשן Claude Code בפרויקט ובודקים: הסקילים מופיעים ברשימת ה-/.
ההוראות הרשמיות מתחילות ממרקטפלייס פלאגינים (/plugin install) ומ-APM CLI - שניהם לא רלוונטיים ברישיון נעול בלי Node. העתקת התיקיות למעלה היא הנתיב המקביל: אותם סקילים, מאותו ריפו, בלי תלויות.

כתיבת דוחות Power BI עם AI (Preview): מהתכנון לפרסום

אוסף הסקילים AI-powered Power BI reporting (פריוויו, יוני 2026) מאפשר לסוכן AI לכתוב דוחות Power BI משפה טבעית: יצירה מאפס, שינוי דוח קיים, ומודרניזציה של עיצוב. זה חלק מספריית Skills for Fabric - ומתקינים אותו בדיוק כמו בפרק הקודם: העתקת תיקיות הסקילים ל-.claude/skills/ בפרויקט.

מה הסוכן עושה בפועל

  • כותב קבצי PBIR תקינים-סכמטית (הפורמט של פרויקטי PBIP) - דפים, ויז'ואלים, סלייסרים, טבלאות.

  • סקיל העיצוב (powerbi-report-design) מייצר "תדריך עיצוב" מסודר לפי עקרונות best practice - ואז מיישמים אותו.

שרת ה-Modeling MCP וכתיבת סמנטיק מודל עם AI

שרת ה-Power BI Modeling MCP נותן לכלי ה-AI גישה חיה לפעולות מידול: קריאה וכתיבה של הגדרות הסמנטיק מודל. בשילוב עם סקיל כתיבת המודל, הסוכן בונה מימדים, טבלאות עובדות וקשרים - ואתה סוקר לפני שמירה.

שימושים מתועדים

  • יצירת סמנטיק מודל מעל lakehouse בשפה טבעית.
  • שינוי שמות ידידותיים בקנה מידה: במודל גדול, לבקש מה-LLM דרך ה-Modeling MCP לייצר שמות עסקיים ברורים לטבלאות, עמודות ומדדים (Totaal Revenue במקום TR_AMT) - קריטי לאיכות תשובות ה-AI על המודל. לסקור ולוודא שהשינוי לא שובר DAX, קשרים או אובייקטים תלויים לפני השמירה.

כלים משלימים (fabric-toolbox)

  • Semantic Link Labs - עדכון המודל תכנותית מ-notebook ב-Fabric, כולל get_measure_dependencies למיפוי תלויות.
  • צ'קליסט הכנה של סמנטיק מודל כמקור לסוכן נתונים.
  • Notebook עם אוסף utilities.
